# Medium mode: a full pass, assembled

Same starting input as `mode-lite-fullpass.md`. This file shows what changes *in addition* to everything Lite already does, and — just as importantly — what a Medium pass usually still leaves alone, since the temptation at Medium is to reach for Ultra-level moves (a full re-theme, a mandatory second page) that don't actually belong here.

## What Medium adds on top of Lite

1. **The question list, made explicit before touching markup.** Before redistributing anything, name what questions this one page is currently being asked to answer at once — typically something like: is everything healthy, what's the trend, how do items compare to each other, what's the overall composition, and which specific item needs action right now. This list is what makes the next steps deliberate rather than improvised.
2. **Redistribution, usually within the same page.** Each question above gets a small purpose-built projection: a glanceable summary metric or two near the top, maybe one comparison or composition view if the page has room, and the row-level detail beneath. At Medium, the strong default is that all of this still lives on the one page, in stacked or grouped sections — a second page is the exception here, reserved for cases where the content has clearly outgrown what one page's hierarchy can hold (many more distinct questions than a page can present without becoming its own new kind of clutter).
3. **Warnings can now be pulled out of their row entirely** into a shared "needs attention"–style zone near the top of the same page, grouping every row currently carrying a warning into one place — this is the Medium-level version of the warning move; Lite could only promote a warning within its own row.
4. **Rows get audited for one-job-per-unit**, now that some responsibilities have moved elsewhere on the page: a row that used to carry an identifier, config, a stat, a warning, and an action can often drop to identifier, one remaining attribute, and an action, because the stat lives in a summary section now and the warning lives in the attention zone.
5. **Pill-vs-text folding happens now**, since it depends on the row actually being restructured (Medium), not just restyled (Lite): values scanned across rows keep their distinct badge treatment; values only confirmed within one row collapse into plain text.
6. **A new shared action surface can appear** (a bulk-select bar, a consolidated toolbar) if the redesign calls for one, since this is a new structural region rather than a row-level rearrangement.

## What Medium still does not require

- **A second page is not the default here** — only reach for it if the redistributed content genuinely can't fit into sections of the one page without recreating the same crowding problem this skill exists to fix. Most Medium passes should still be judged first against "can this fit as sections on one page," and only escalate to a second page when that answer is clearly no.
- **The color system is not being rebuilt.** Medium can nudge existing colors (a status color gets a proper ink/soft-background pairing, say) but does not redo the whole tonal ramp or reconsider which region gets which treatment by dwell time — that reasoning is Ultra-only, because it's a full re-theme rather than an adjustment.
- **Depth/elevation stays roughly as it was** (maybe a shadow or two nudged), rather than a full elevation system being designed from nothing.

## How to tell if a "Medium" result actually stayed Medium

Two opposite drift risks to check for: did it under-deliver by staying exactly Lite (no redistribution actually happened, just nicer type)? Or did it over-deliver into Ultra territory (a full palette rebuild happened, or a second page appeared without a clear "this page had genuinely outgrown one page" justification)? A correct Medium result sits distinctly between both — visibly more restructured than Lite, but recognizably a lighter, more contained effort than a full Ultra rebuild.
