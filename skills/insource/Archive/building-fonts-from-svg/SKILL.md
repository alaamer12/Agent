# Building fonts from SVG

Pipeline: one SVG per character, each unioned into a single clean outline, converted to TrueType quadratics, then assembled into a font with character map, metrics and names. The SVGs are either supplied by the user or generated by a script from stroke primitives.

## Scope

**Includes**
- Compiling a folder of SVGs into a monochrome `.ttf` (any characters: letters, digits, punctuation, accented letters drawn as whole glyphs).
- Generating those SVGs from code with reusable primitives (`scripts/glyph_kit.py`), so a whole alphabet is defined in one script.
- **Arabic and other context-shaped scripts**: a letter drawn once yields its isolated/initial/medial/final forms, and the build wires up the GSUB `init`/`medi`/`fina` features so HarfBuzz joins words. Read `references/arabic-shaping.md`.
- Verifying the font and rendering a specimen image (Arabic specimens are rendered through HarfBuzz so they actually join and run right-to-left).
- `.woff`/`.woff2` export, and optional kerning as a post-step.

**Does not include** (say so plainly, then point to `references/extending.md` for alternatives): icon fonts, color or variable fonts, CFF `.otf` outlines, hinting, ligatures, Arabic tashkeel (vowel marks) or Indic complex-script shaping, combining accents onto base letters, editing or converting existing fonts, tracing raster images.

## Setup

```bash
pip install fonttools skia-pathops pillow    # add brotli for .woff2
pip install uharfbuzz                        # needed to render Arabic specimens (shaping)
```

Run scripts by absolute path or from the skill folder.

## Workflow

Copy this checklist and tick it off:

```
- [ ] 1. Pin down the character set and the look
- [ ] 2. Fix the grid
- [ ] 3. Produce the SVGs
- [ ] 4. Build
- [ ] 5. Verify and look at the specimen
- [ ] 6. Deliver
```

1. **Character set and look.** Ask only for what is missing. List every character up front (A-Z, a-z, 0-9, punctuation) so they can be made in one pass.
2. **Grid.** Default: `viewBox="0 0 W 700"`, y=0 is cap height, y=700 is the baseline, 1 SVG unit = 1 font unit. Every glyph must share it. Read `references/svg-requirements.md` when the user supplies SVGs or when any glyph needs a descender.
3. **SVGs.**
   - *User-supplied:* name each file by code point (`uni0041.svg`), then go to step 4.
   - *Generated:* copy `examples/shardsans/make_letters.py`, keep its grid, replace the stroke recipes. Define all glyphs in one script and run it once; do not hand-write files one by one, because a script keeps the set consistent and lets you restyle by changing one number.
   - *Arabic:* copy `examples/arabic/make_letters.py` instead — it draws one skeleton per letter and derives the four forms; build with `--baseline 700 --side-bearing 0 --tracking 0` so the joining spine lines up.
4. **Build.**
   ```bash
   python scripts/build_font.py svgs --family "My Font" --out MyFont.ttf [--web]
   ```
   Common flags: `--side-bearing`, `--tracking`, `--baseline`, `--ascender`, `--descender`, `--scale`. See `--help`.
5. **Verify.**
   ```bash
   python scripts/check_font.py MyFont.ttf --text "HELLO WORLD" --png specimen.png
   ```
   Fix every `PROBLEM`, then open the PNG and judge it: letters legible, strokes solid where they join, letters resting on a common baseline, spacing even. For Arabic, install `uharfbuzz` so the specimen is shaped — an unshaped PNG shows reversed, unjoined letters and is **not** a font bug. Iterate on the recipe script and rebuild; never patch generated SVGs by hand.
6. **Deliver.** Give the user the `.ttf` (and web formats), the specimen PNG, and the generator script with its SVGs so the font can be regenerated.

## Why the build works this way

- **Strokes are unioned per glyph.** TrueType fills by winding direction, so overlapping shapes drawn in opposite directions cancel into holes. `build_font.py` resolves each element, then unions them; overlapping strokes in the SVGs are safe and are the easiest way to draw.
- **The baseline is explicit.** SVG y grows downward and font y grows upward, so the build computes `(baseline - y) * scale`. Without the offset every glyph lands under the line.
- **Counters need `fill-rule="evenodd"`.** Holes belong in the same path as the outline, never as white shapes on top.
- **Names are by code point.** `a.svg` and `A.svg` collide on Windows and macOS.
- **A build that succeeds proves little.** The checker catches structural faults, only eyes catch ugliness, so always view the specimen.

## Files

| Path | Use it for |
|------|-----------|
| `scripts/glyph_kit.py` | Primitives: `bar`, `ribbon` (bent stroke), `burst`, `poly`, `write_glyph`. `jag=0` is clean, higher is fractured. |
| `scripts/build_font.py` | SVG folder to `.ttf` / `.woff` / `.woff2`. |
| `scripts/check_font.py` | Structural checks and specimen PNG. |
| `references/svg-requirements.md` | Read before accepting user SVGs, adding descenders, or exporting from design tools. |
| `references/font-metrics.md` | Read when changing spacing, proportions, or when glyphs are clipped. |
| `references/troubleshooting.md` | Read when the checker reports a problem or a glyph looks wrong. |
| `references/extending.md` | Read for lowercase, digits, accents, kerning, CSS `@font-face`, or any request outside the scope above. |
| `references/arabic-shaping.md` | Read before building Arabic (or any context-shaped script): the four forms, the shared spine, GSUB, and shaped verification. |
| `assets/templates/` | Hand-drawn glyphs with a counter and cubic curves; copy to start drawn-by-hand letters. |
| `examples/shardsans/` | Finished worked example: generator, SVGs, `ShardSans.ttf`, web formats, specimen. |
| `examples/arabic/` | Finished Arabic example: generator (one skeleton per letter -> four forms), SVGs, `ArabicSans.ttf`, connected RTL specimen. |
