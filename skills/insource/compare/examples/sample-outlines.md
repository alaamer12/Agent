# Sample Comparison Outlines

Illustrative skeletons only. Adapt depth and dimensions to the actual task.

## Technology frameworks (open-ended)

1. Framing (decision context + why comparing now)
2. Initial load / TTI
3. Reactivity model and update cost
4. Memory and resource behavior
5. SSR / streaming story
6. Payload and network efficiency
7. Developer experience and ecosystem
8. Fits-if section

## Two source files (dimension-based)

1. Framing (what the files are, what the user needs to decide)
2. Responsibility / purpose
3. Public surface / API
4. Error handling and edge cases
5. Test coverage and testability
6. Dependencies and coupling
7. Fits-if / which to keep or merge

## Two projects / repositories

1. Framing (goal of the comparison)
2. Architecture and module boundaries
3. Onboarding and documentation quality
4. Test strategy and CI health
5. Dependency footprint and supply-chain surface
6. Performance or resource characteristics (if relevant)
7. Maintainability signals (coupling, duplication, ownership clarity)
8. Fits-if for the user's stated constraints

## Two books / papers

1. Framing (purpose of the comparison)
2. Central thesis / claim
3. Evidence quality and methodology
4. Scope and audience
5. Strength of conclusions
6. Clarity and usability for the reader
7. How to tell them apart / which to reach for when
