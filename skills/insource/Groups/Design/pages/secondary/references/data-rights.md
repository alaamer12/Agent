# Data rights requests (access / export / rectify / portability)

The mechanism the Privacy Policy promises. One document covers the request menu; each right's
SUBSTANCE belongs to `privacy-policy.md` (one owner) - this page is the how.

## Must include

1. **The menu** - access ("what do you hold on me"), export/portability (format named:
   [JSON]/[CSV]/store-standard), rectification, objection/withdrawal (and which processing it
   stops), deletion (pointer to `delete-account.md` when that is the stronger tool).
2. **Who may ask** - the account holder, or a verified agent (some laws admit authorized agents);
   the identity-verification step stated plainly ("we confirm it is your account before answering
   - here is what that means").
3. **The route** - self-service export where it exists (the real click path per platform),
   otherwise the request channel; where an inbox exists, one address and the required evidence.
4. **The clock** - statutory windows differ by frame ([GDPR one month], [CCPA 45 days]); which
   applies is the operator's jurisdiction answer (ASK), and the page commits to the real response
   time - the one support promises can meet.
5. **What a reply contains** - export shape, where data came from (categories/sources), the
   rectify outcome, and the escalation route if the answer disappoints (the supervisory authority
   where the law offers one - named only for users it actually covers).
6. **No-fee / refusal grounds** - only the honest ones ("we do not charge for requests"; refusal
   reasons the law allows, stated as allowed).

## Writing professionally

- Identity verification is the paragraph that decides whether this page is real: it protects
  requesters - explain what is asked and why, never as a hurdle without a reason.
- The page must match the backend: a JSON export promise with no export job implemented is the
  failure - verify code or mark `pending`.

## Ask the user - never invent

Which routes exist today; verification method; response windows per jurisdiction set; export
format truth; the supervisory/authority lines that apply; who handles these tickets.
