# Anti-fraud / Official channels

The impersonation defense: one page that lists what is REAL - domains, apps, accounts, phone
behavior - so users can spot the fake. Highest value for money-adjacent products and anything with
regional popularity scammers already target; skip it only when the product is not impersonable
(and that judgment is the user's - it is cheap insurance and worth one line in the report).

## Must include

1. **The canonical list** - every official domain (exact, config-sourced), every official store
   listing, verified social handles with the platform's own verification visible, official sender
   addresses ("we email only from these domains"), and support's real phone behavior.
2. **What we NEVER do** - the honest list per product truth: never ask for passwords or codes,
   never DM first from unofficial handles, never request payment via [channel], never offer
   "support" via phone numbers users found in ads. - each line is a fact about the OPERATOR: ASK,
   never assume.
3. **How scams look here** - concrete patterns seen or expected (refund scams, "verify your
   account" phishing, fake investment ads in the product's name) - specific warnings, not
   generalities; the patterns come from the operator's real abuse experience (ASK).
4. **What to do if targeted** - the reporting channel, what evidence preserves the case, and the
   reassurance line that reports get read (only if `support.md` can back it).

## Writing professionally

- Shareable: this URL is what support pastes into tickets and what the app links from its
  "official app" screen; short, listy, screenshot-proof, no jokes.
- Keep it updated: an official-handle list with a dead account in it becomes scammer ammunition -
  changes to any listed channel edit this page in the same change (the `agents-md` sync duty, same
  shape).

## Ask the user - never invent

Every channel on the canonical list; the never-do list against actual team practice; known scam
patterns; the report route.
