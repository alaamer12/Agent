# Cookie / Tracking Policy

The tracker-level detail the Privacy Policy summarizes. Only needed where a web surface sets more
than strictly-necessary storage - filter honestly: a static site with zero JS analytics does not
need this document at all.

## Must include

1. **What cookies/storage are used** - literal, named categories: strictly necessary (session,
   CSRF), preferences, analytics, marketing. Device-fingerprinting and localStorage misuse get
   named too - the document covers "tracking storage", not just cookies.
2. **Per-cookie table** - name | purpose | lifetime | first/third party. Generated by auditing the
   real requests (the repo/network tab, not a vendor's default list); an unlisted live cookie is a
   breach of this page's own promise.
3. **Consent mechanics, stated truthfully** - which categories are off until consent (EU: all
   non-essential), whether "reject" is as easy as "accept" (it must be), where settings live, and
   that withdrawal works as easily as granting.
4. **Third parties** - each vendor named with ITS policy link (their cookies, your page - the
   reader deserves the bridge).
5. **Do-not-track signals** [GPC / global privacy control] - honored or not: ASK; "we honor GPC"
   must match the banner's actual behavior.
6. **How to stop cookies** - in-app controls plus the browser-level truth.

## Writing professionally

- Same first sentence discipline: "This site uses 3 cookies: one to keep you logged in, two
  [vendor] analytics you can decline."
- The banner and this page must not contradict - the banner is the page's runtime; when banner
  behavior changes, edit the document in the same change.
- The cookie canon lives here; the Privacy Policy links here instead of restating tables.

## Ask the user - never invent

Which trackers actually run (verify against code first); consent posture by jurisdiction; GPC
stance; any marketing pixels and who operates them.

## Failure patterns

A 40-row vendor list pasted from a generator while the site sets two cookies; a banner whose
"decline all" still writes analytics storage (the document now describes a site that doesn't
exist); no page created even though trackers run - the worst of both.
