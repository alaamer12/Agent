# `PAGE-MAP.md` format

One file, written at the project root (or the path the user specifies). It is the contract every
downstream skill reads: `prototype`, `impeccable`, `planner`, and any implementation skill. Keep
the section order stable so tools and humans can find things.

---

## Skeleton

```markdown
# Page Map — <Project Name>

> Generated by `main-pages` on <YYYY-MM-DD>. Source of truth for the screen set.
> Changes: update this file in the same change that adds, removes, or renames a screen.

## 1. Context

| Field | Value |
|---|---|
| Product | <one line> |
| Discipline | <from data.csv, e.g. healthcare + saas-b2b> |
| Platforms | web / iOS / Android / desktop / embedded |
| Roles | <role list> |
| Sources read | <docs, routes, entities, decisions> |
| Scope of this map | <v1 / MVP / whole product> |

## 2. Legend

Status — how settled the screen is:

| Mark | Meaning |
|---|---|
| `confirmed` | Direct evidence in docs, routes, entities, or a recorded decision |
| `inferred` | Domain logic implies it; not yet confirmed by the project |
| `uncertain` | Needs a user decision; listed in Open Decisions |
| `excluded` | Considered and deliberately not built; see Exclusions |

Kind — what the unit is:

| Kind | Meaning |
|---|---|
| `page` | Top-level route with its own job |
| `subpage` | Deep-linkable concern inside a hub or parent |
| `modal` | One short decision; not linkable |
| `state` | Not a route; a condition of another screen |
| `redirect` | Route exists only to hand off; see Redirects |

## 3. Roles and surfaces

| Role | Landing route | Sees | Does not see |
|---|---|---|---|
| Member | `/dashboard` | own work, workspace content | billing, admin |
| Admin | `/admin` | members, billing, audit | — |
| Guest | `/login` | marketing, auth | anything behind auth |

If a platform has a different screen set, add a **Surface notes** column to the category tables
rather than duplicating the whole map.

## 4. Categories

### Auth

Purpose: identity, access, and account recovery.

| Screen | Route | Kind | Status | Confidence | Evidence | Notes |
|---|---|---|---|---|---|---|
| Login | `/login` | page | confirmed | high | `docs/auth.md` | email + password; SSO link |
| Signup | `/signup` | page | confirmed | high | `docs/auth.md` | invite-only alternative |
| Forgot Password | `/forgot-password` | page | confirmed | high | `docs/auth.md` | sends magic link |
| Reset Password | `/reset-password` | redirect | excluded | high | `DECISIONS.md` §auth | magic link only; redirects to `/forgot-password` with notice |
| Verify Email | `/verify-email` | page | inferred | medium | domain logic | needed if email verification is on |

### <Next category>

Purpose: <one line>.

| Screen | Route | Kind | Status | Confidence | Evidence | Notes |
|---|---|---|---|---|---|---|

## 5. States

Shared states that are not routes. Add per-screen states in the Notes column when they are
screen-specific.

| State | Applies to | Planned | Notes |
|---|---|---|---|
| Loading | all async screens | yes | skeleton, no layout shift |
| Empty | list screens | yes | first-run guidance, not a blank page |
| Filtered empty | search and lists | yes | clear filters action |
| Error | all async screens | yes | retry, preserve input |
| Success | forms and mutations | yes | toast or inline |
| Unsaved changes | all forms | yes | navigation guard |
| Session expired | authenticated screens | yes | re-auth, return to route |
| Permission denied | role-gated routes | yes | inline; 403 for direct URL |
| Offline | mobile / PWA | <yes/no> | cached read-only state |

## 6. Splits

Records screens that were one screen and were divided.

| Was | Became | Tests that justified it | Date |
|---|---|---|---|
| Settings | `/settings/profile`, `/settings/security`, `/settings/notifications`, `/settings/billing` | model, complexity, audience, deep-link | <date> |
| Project detail | `/projects/:id` (overview), `/projects/:id/work`, `/projects/:id/settings` | back, deep-link, complexity | <date> |

## 7. Exclusions

Every screen considered and deliberately not built.

| Screen | Route | Decision | Reason | Source | Revisit when |
|---|---|---|---|---|---|
| Reset Password | `/reset-password` | excluded | passwordless product; magic link only | `DECISIONS.md` §auth | password auth is added |
| Shipping Policy | `/shipping` | excluded | no physical goods | product brief | physical goods launch |
| Admin panel | `/admin` | deferred | v1 is single-user | `PLAN.md` | multi-user launch |
| Social login | `/auth/google` | excluded | enterprise SSO only | `DECISIONS.md` §identity | consumer launch |

`decision` is one of `excluded` (will not build), `deferred` (may build later), `redirect`,
`state`, or `owned-elsewhere` (another skill or surface owns it).

## 8. Redirects

| From | To | Type | Reason | Source |
|---|---|---|---|---|
| `/settings` | `/settings/profile` | 302 | hub has no standalone content | this map |
| `/signin` | `/login` | alias | common alternate name | this map |
| `/reset-password` | `/forgot-password` | alias + notice | passwordless flow | `DECISIONS.md` §auth |

## 9. Open decisions

Anything the user deferred. These are TODOs, not gaps.

| Decision | Options | Owner | Needed by |
|---|---|---|---|
| Team accounts in v1? | yes / no / later | <user> | before auth build |
| Dedicated reset page? | page / magic link | <user> | before auth build |

## 10. Coverage

| Check | Result |
|---|---|
| Categories | 6 |
| Routes | 38 |
| Confirmed screens | 31 |
| Inferred screens | 7 |
| Excluded decisions | 9 |
| Redirects | 3 |
| Open decisions | 2 |
| Every entity has list + detail | yes |
| Every role has a landing route | yes |
| Every destructive action has a confirmation state | yes |
| Every async screen has the shared states | yes |
| Secondary documents handed to `secondary-pages` | ToS, Privacy, Cookies |

## 11. Change protocol

1. Add, remove, or rename a screen only by editing this file in the same change.
2. A removed screen moves to **Exclusions** with a reason — never disappears silently.
3. A split records the old route in **Redirects**.
4. A changed decision supersedes the old row with a date and a source link.
5. Downstream skills read this file; they do not maintain their own screen list.
```

## Field rules

| Field | Rule |
|---|---|
| `Screen` | Human-readable name the user would recognise. Match the user's vocabulary. |
| `Route` | One canonical route. Aliases go in Redirects. `-` only for states. |
| `Kind` | `page`, `subpage`, `modal`, `state`, `redirect`. |
| `Status` | `confirmed`, `inferred`, `uncertain`, `excluded`. Never leave blank. |
| `Confidence` | Confidence in the screen's existence, not in the design. `high` needs evidence. |
| `Evidence` | File path, doc section, route file, ticket, or `domain logic`. No vague "common". |
| `Notes` | Scope caveat, split pointer, state note, or redirect target. Keep short. |

### Status rules

- `confirmed` requires a source in `Evidence` that a reader can open.
- `inferred` is the default for domain-logic candidates. Never label a guess `confirmed`.
- `uncertain` must have a row in **Open Decisions**.
- `excluded` must have a row in **Exclusions** with a reason and a revisit trigger.
- A screen that is `excluded` may still have a `Route` when a redirect exists.

---

## Writing rules

- **One row per screen.** Do not group two routes in one cell.
- **No orphan categories.** A category with no screens is deleted, not left as a heading.
- **No empty tables.** Omit a section that does not apply (e.g. Splits) rather than shipping a
  heading with no rows.
- **Counts must match.** The Coverage table is computed from the sections, not estimated.
- **Dates are real.** Use the session date; never a decorative "last updated".
- **Links resolve.** Evidence paths and cross-references must exist at write time.
- **The map is not a design doc.** No layouts, colours, or component choices. Those belong to
  `prototype`, `impeccable`, or the design system.

---

## Downstream contract

| Consumer | Reads | Expects |
|---|---|---|
| `prototype` | Categories, Routes, States | One page per confirmed route; states as variants |
| `impeccable` / design | Categories, Roles, States | Screen set and role surfaces |
| `planner` | Categories, Splits, Exclusions | Work breakdown that respects the map |
| `secondary-pages` | Exclusions (`owned-elsewhere`) | Documents it must create |
| Implementation | Everything | No inventing screens outside the map |

When a downstream skill needs a screen the map lacks, the correct move is to update the map first,
then build. A screen that exists only in code is a map defect.
