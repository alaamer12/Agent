# Constraint derivation: ruling directions in and out on a real input

One instance among many — an ops console, three directions asked for. The point is the
*method*: look at what is actually fixed about the input, ask what is plausible given it,
reject options that don't fit rather than forcing them in to reach a count. Never copy the
specific answers below into an unrelated product; derive your own from its own evidence.

## The input

A build-operations console: a persistent dark side rail with text labels (~8 items across
two labeled sections), a dense single-column list of source rows (one source per row, each
with independent state), a light working surface, dark chrome, a red brand accent. The
person asks for `/diverge taste 3` before rolling a redesign across the project.

## Step 1 — what does this input rule in or out, axis by axis?

- **Chrome position.** The item count is moderate and the labels are already short, so a
  top bar or a slide-out panel are both plausible alternates to the side rail — live axis.
  An icon-only nav is a weaker fit: items like "Runs & workers" aren't obviously
  iconographic. Say so rather than proposing it anyway just to fill out a list.
- **Working-surface light/dark.** This is a data-dense console read for long stretches.
  The light surface is a dwell-time decision, not an inherited accident — going all-dark
  would trade away the long-read rationale. **Not a live axis here.** Building a dark
  direction anyway to reach three manufactures an option that should be rejected on
  inspection; if raised at all, flag it as a tradeoff, never as one bullet among equals.
- **Chrome colour.** Independent of the surface direction. Dark-neutral (current),
  light-neutral, and full-brand-hue rail are all live — a red rail over the light working
  surface is a bold, genuinely-different direction that costs nothing in legibility.
- **Row shape.** Each source has independent state and no inherent chronological ordering
  requirement, so a grid-of-tiles or a timeline-by-run-date are both structurally plausible
  alternates to the dense list — live axis.
- **Tonality.** Nothing about an ops console demands the current warm neutral + red
  specifically; a cooler neutral, or concentrating the accent differently, are real
  options — as long as the brand stays recognisable somewhere prominent.

Result: four open axes (chrome position, chrome colour, row shape, tonality), one closed
(working-surface direction). Three directions must vary across the open ones.

## Step 2 — coherent combinations, not stapled answers

- *A: "quiet rail"* — side rail kept but light-neutral, comfortable scale, list rows
  preserved with calmer encoding. Coherent: the conservative product, refined.
- *B: "brand rail"* — full-brand-hue top bar, light surface, grid-of-tiles. Coherent: the
  chrome carries the identity so the working surface can stay calm; tiles suit independent
  per-source state.
- *C: "timeline"* — collapsible light panel, cooler neutral, timeline-by-run-date.
  Coherent: run date becomes the organising axis, which the content supports.

A combination like "enormous scale + floating collapsible chrome + dense timeline" would
fail here: the floating panel eats the screen space the enormous scale already spent.
Interaction between axes rules it out; it is not presented as equally coherent.

## Step 3 — spread check

A is a refinement of the input; B and C are genuinely different overall feels. At least one
direction differs structurally (row shape, chrome position), not just in paint — satisfied.
None of the three varies the closed axis. If step 1 had left only one open axis, the honest
move is to say so and deliver fewer genuinely-different directions (or ask), not to fake
spread on an axis the input has already decided.

## What this example is evidence against

- Picking combinations first and checking plausibility later — the closed dark-surface axis
  would have slipped in as "direction C, but dark".
- Offering options that don't fit the input's actual constraints to look thorough — the
  icon-nav counterexample.
- Treating every "different" direction as a good-faith offer — an alternate that undoes a
  reasoned decision from the input is a tradeoff to name, if named at all, not a neutral
  option.
