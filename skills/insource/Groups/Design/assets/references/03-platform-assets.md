# Platform assets — current specifications

Sources are listed at the bottom. Platform rules change (Apple changed icon guidance as recently as
October 2026), so when the target is a real store submission, re-check the source before shipping. The
numbers below are what the platforms currently specify, not what this skill's memory says.

## Apple (iOS / iPadOS / macOS)

Per the Human Interface Guidelines (App icons, updated October 28, 2026):

- **Layout size is 1024x1024 px** for iOS, iPadOS and macOS. The system **scales the icon itself** for
  Settings, notifications and other smaller slots - you do not hand-cut a list of pixel sizes for a
  modern project.
- **Format options:** layered icons (Icon Composer, exported from Xcode) are preferred for Liquid Glass
  effects and dark/clear/tinted appearance variants; a **non-layered bitmap (PNG)** is still accepted,
  and the system segments it into two layers. A bitmap icon must be **opaque** - no alpha channel.
- **Shape:** provide a **square, unmasked** layer; the system applies the rounded mask. Pre-masking
  hurts the system's highlights.
- **Appearances:** default, dark, clear light, clear dark, tinted light, tinted dark. Variants you do
  not supply are generated by the system; alternate app icons need their own variants.
- Other Apple platforms have their own sizes (tvOS 800x480, visionOS 1024x1024 circular mask, watchOS
  1088x1088 circular mask) - check the table in the HIG.
- **Splash:** Apple's launch-screen guidance uses a launch screen (storyboard/asset), not a static
  splash image per device. `splash.py` output is useful for design deliverables and non-Apple
  frameworks; for a real iOS app prefer the launch screen mechanism.

What the script does: `gen_icons.py --app-icons --platform ios` generates the **legacy asset-catalog
size list** (20..1024) for projects whose catalog still declares explicit sizes; for current Xcode,
ship the 1024 (or Icon Composer layers) and let the system scale. `--pad-color` flattens alpha, which
the store icon requires.

## Android

Per Android developer documentation and the 2026 icon-size guides:

- **Launcher baseline is 48 dp**; legacy launcher icons ship as `mipmap-*` densities:
  mdpi 48, hdpi 72, xhdpi 96, xxhdpi 144, xxxhdpi 192 px.
- **Adaptive icons** (Android 8+) use a **108x108 dp canvas** with foreground/background layers plus a
  masked safe zone (the outer 18 dp on each side is reserved for system effects) - place them under
  `mipmap-anydpi-v26/` XML references. Generate the legacy raster set from the same source with
  `gen_icons.py --app-icons --platform android`.
- **Google Play store icon:** a separate **512x512 px** asset, not the launcher icon
  (`gen_icons.py --sizes 512`).
- **Splash:** since **Android 12**, the system builds the splash screen from the **app icon** via the
  SplashScreen API (icon + window background). A custom full-screen splash image is legacy - use it
  only for frameworks/OS versions that still consume static images, and ask the user before adding
  one. `splash.py --preset android` covers those legacy targets.

## Web

- Favicon essentials (multiple 2026 guides converge): **16x16 and 32x32** (ICO or PNG - one ICO with
  both sizes is fine), **180x180 apple-touch-icon**, **192x192 and 512x512** for the web app manifest
  (512 can be `maskable`). A modern optional addition is an **SVG favicon** for browsers that support
  it. `gen_icons.py --favicon` writes the whole conventional set.
- **Open Graph / social preview:** **1200x630** remains the common recommendation (1.91:1); keep the
  title large and the logo small enough to survive cropping. `og_image.py` defaults to that size.
- **Loading screen:** still a product decision (logo / image / nothing) - ask.

## Ask-user checklist (unchanged)

1. Loading/splash: logo, a specific image, or plain?
2. If logo: which file, on which background color?
3. Icon: source logo? does the platform require opaque (Apple: yes)?
4. Colors for backgrounds and OG templates.
5. Where brand assets live, if the project has no convention.
