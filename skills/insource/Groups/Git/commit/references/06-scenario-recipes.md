# Scenario recipes

Full messages for the shapes that come up constantly. Match the *structure*, not the wording; and remember
[`04`](04-conventions-and-when-to-drop-them.md) - if the repo does not use type prefixes, drop them here too.

## A defect fix - name the cause, not the symptom

```text
fix(orders): stop double-charging retried payment webhooks

The retry loop re-sent payloads on every 5xx, including 501/503 which the
processor treats as permanent failures. Those retries kept the queue hot and,
because delivery ids were regenerated per attempt, the processor could not
deduplicate - so a customer could be charged twice.

Retries are now limited to 429, 502 and 504 with Retry-After honored, and the
delivery id is derived from the order id so a duplicate attempt deduplicates
upstream. Adds a regression test that replays a recorded 503 sequence.

Fixes #4821
Reported-by: Support <support@example.com>
```

The reusable moves: cause named, mechanism explained, prevention described, test mentioned, and the reader
learns something they cannot get from the diff.

## A refactor with no behavior change

```text
refactor(pricing): extract tax rounding into a pure function

Checkout needed to compute rounding the same way in three places, and each call
site built a cart first. Extracted into `roundTax(cents, jurisdiction)` so the
currency rules can be unit-tested without the handler.

No behavior change intended. Two legacy rounding differences were left intact
and marked with a TODO each - they need a product decision, not a refactor.
```

Saying "no behavior change intended" is a claim you must be able to defend. If you are unsure, do not write
it; write what you observed instead.

## Performance

```text
perf(list): avoid re-rendering rows on each filter keystroke

The filter input wrote to a context every row subscribed to, so typing
re-rendered 2,400 rows per character. The input now holds its own state and
commits on a 150ms debounce.

p95 interaction time 180ms -> 22ms on the 2k-row account, measured with the
existing perf harness. Cursor position during typing is unchanged.
```

Numbers come from a measurement you ran. No measurement, no number.

## Dependency bump - the version is the subject, the reason is the body

```text
chore(deps): upgrade http client 2.4.1 -> 2.7.0

2.7 adds per-request timeout support, which the export path needs to stop
hanging on slow proxies. Also pulls a transitively-vulnerable older tls lib out
of the tree.

Tested: full suite plus the export integration test against the staging proxy.
One behavioral note - connection reuse is now capped at 10 per host, which our
load profile does not reach.

Refs #5102
```

Routine bumps with no behavior effect can be a bare one-liner. The body is for the *reason* and the
*behavioral side effects a reviewer would otherwise discover later*.

## Generated code

Commit generated output **together with the source that produced it**, in the same commit, so the tree is
never internally inconsistent - and say which file is generated:

```text
feat(api): add the bulk-export endpoint

New POST /api/v1/exports plus the regenerated OpenAPI document and typed client.
openapi.json and gen/client.ts are generated by `make api-codegen`; do not edit
them by hand.

Closes #4970
```

## A migration

```text
fix(db): backfill the missing created_at index

The table gained a created_at column in 2024 without an index, so the export
query sorts on every call. This adds the index via a concurrent migration; it
must run outside a transaction and takes about 6 minutes on production volume.

Deploy order: run the migration before shipping the export change that relies on
it. Rollback is a plain DROP INDEX.
```

Deploy/rollback order is exactly the kind of thing that cannot live in the diff.

## Documentation, CI, and housekeeping

```text
docs: document the two-step local env setup
```

```text
ci: run the test job only when the suite is affected

The full suite takes 14 minutes and ran on docs-only pushes. Path filters it to
source, tests and the workflow file itself.
```

```text
style: run prettier 3.3 over the tree (no logic changes)
```

That last one is a formatting-only commit and must contain nothing else ([`03`](03-atomicity-and-staging.md)).

## Checkpoints: WIP is a legitimate stage, not a legitimate final commit

Local checkpoints are fine while you work (`wip: probe the retry path`), but they get squashed, reworded, or
dropped before anything is shared ([`07`](07-history-hygiene-and-hooks.md)). Never push a `WIP` commit to a
shared branch as your final word, and never leave `fix stuff` in a branch that a release will be cut from.

## Security fixes - two different obligations

```text
fix(auth): reject tokens with an empty scope claim instead of granting admin

An absent scope array was treated as "all scopes" by the policy check. Now a
missing scope claim is an error path, and the default is no access.

Fixes #5140
Reported-by: External researcher (responsible disclosure, 90 days)
```

A security commit's subject **describes the vulnerability** - which is exactly what you must not publish
before the fix is out. Handle it by convention: keep the private repo private until release, or land a
minimal "fix(auth): harden token scope handling" commit and expand the description later, and never put
exploit steps, PoC payloads, or the reporter's personal data in a message that is about to be public. When in
doubt, ask the person who owns disclosure policy rather than deciding mid-commit.
