## Deliberately not presented as fact

- **Git Flow as a default.** It is one row in a table, and the recommendation against `develop` for new projects is
  an opinion shared by the sources above, not a standard. If a team ships several maintained versions, it is
  correct.
- **The claim file's format.** `.git/agent-branch` + `refs/agent/*` is this skill's design, not an industry
  standard. What is standard is the reasoning: git offers atomic ref creation, `.git` is the only directory every
  agent sharing the repository will see, and refs are already the mechanism git uses to say "this exists".
- **Durations.** "Two weeks is long-lived", "merge within a day", "8–10 worktrees" are thresholds quoted from the
  sources above as reasonable defaults. The project's real constraint (review latency, CI duration, deploy
  cadence) beats a number from an article.
