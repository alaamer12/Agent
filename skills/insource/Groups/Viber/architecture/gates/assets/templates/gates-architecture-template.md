# Gates Architecture — <Project Name>

> Generated by `architecture/gates` on <date>. Binding for every enforcement check in the project,
> including checks written later by agents. Precedence: a green gate is evidence only for the rule it
> names; an unregistered rule is advisory.

## 1. Scope & Boundaries

- Owns: the enforcement ladder and the rung chosen per rule class, the tier table and budgets, the
  gate register, the fail-closed and exit-code contract, the baseline and ratchet policy, the
  suppression and exception process, the agent completion contract, and the inventory census.
- Does NOT own: the content of the rules. Types and compiler strictness belong to
  `language-architecture.md`; failure payloads to `error-architecture.md`; test design and
  conformance tests to `testing-architecture.md`; schema and constraints to `db-architecture.md`;
  extension contracts to `plugin-architecture.md`; platform and vendor seams to `seams-architecture.md`;
  asset policy to `media-architecture.md`. This document decides where those rules are enforced, at
  what cost, and what happens when they fail.

## 7. Agent Contract

- Fast command: `<command>` (p95 <n> s). Full command: `<command>`.
- A task is done only at exit 0 on: <required gates>. Warnings are not done.
- Completion hook: <hook name / none>; if none, the agent must paste the command and exit code.
- Protected paths (agent may read and run, not edit): `gates/**`, `<ci config>`, baselines,
  exceptions, canary fixtures, <test fixtures>.
- Large diff (more than <n> files): run the full scan.
- Report path: `<.reports/gates.json>`; summary mode: `<command>`.
- The agent may propose an exception with a reason and an expiry; it may not approve one.
- Forbidden shortcuts: edit the check, delete/weaken a test, add `any`/`@ts-ignore`, empty `catch`,
  `--no-verify`, `continue-on-error`, hardcode the expected value, skip a missing dependency, hide a
  warning.
- Evidence to paste: command, exit code, finding count, report path. Never "I ran the tests."

## 8. Failure, Bypass & Flake Policy

| Status | Meaning | Blocks? | Owner | Message |
|---|---|---|---|---|
| PASS | ran, scope non-empty, no finding above threshold | no | gate owner | summary + duration |
| FAILED | ran, violations found | yes | finding owner | rule, file, line, impact, fix |
| ERROR | could not run (crash, missing report, timeout, unparsable, empty scope) | yes | platform | what failed, log path |
| SKIPPED | did not run (condition, dependency, quota) | yes unless a recorded waiver | platform | why, waiver id |

- Exit codes: 0 pass, 1 failed, 2 error. Third-party tools are normalized by a wrapper; the wrapper's
  code is the gate.
- A missing report is an error; a timeout is an error; an empty scope is an error.
- `continue-on-error` is forbidden on a required job.
- Flaky check: removed from blocking, fixed, returned; quarantine has an owner and an expiry; retries
  only in non-blocking lanes.
- Bypass: <who>, <how>, <record>, <expiry>; bypass count is reviewed monthly.

## 10. Census, Metrics & Review

- Census: `<command>` asserts every rule in the manifest has a gate or an advisory reason; every
  active gate has a command, tier, owner, exception policy, and evidence; every deprecated gate has
  a replacement; no duplicate ids; sanity floor <n> rules.
- Metrics: p50/p95 duration, false-positive sample, suppression count, exception age, bypass count,
  baseline trend, flake rate, time-to-fix, evidence freshness, rule coverage.
- Review cadence: <monthly> tier/budget and bypass; <quarterly> register, stale gates, expired
  exceptions, advisory list.
- Incident loop: every postmortem answers "which gate would have caught this?" with a gate, a fix, or
  a written "cannot be gated" and a compensating control.
