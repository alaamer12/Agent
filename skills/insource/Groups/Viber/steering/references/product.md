# product

> This document defines the `product` steering folder: the product-level overview of what is delivered to users. It is one of six folders; see the [index](index.md) for the set.
> **Terminology reminder.** The steering folder whose directory name is `function` is always called the **steering function folder**, never just "function". Full rule: [function.md](function.md).

**Holds.** The product-level overview of what is delivered to users: purpose, target users, key features at a high level, and business objectives. This is the same level of knowledge as Kiro's `product.md`, which "defines your product's purpose, target users, key features, and business objectives" so the agent understands the "why" behind technical decisions.

**Does not hold.** The detail of any single feature. That belongs with that feature's own documentation (see [placement.md](placement.md)).

**The test.** Product answers "what is this and why does it exist?" about the whole product. If it is about one feature, it is not product.

**Caveat.** The description of Kiro's `product.md` rests on public tutorials and community documentation retrieved while writing this, not on a full reading of Kiro's official page. Sources are listed in the [index](index.md#references).
