# Intake

Ask these in one short message. Skip any the user already answered. If an interactive question tool exists, use it for the closed questions.

## Questions

1. **Goal and constraints.** What are they building or deciding? What matters most (speed, cost, team skills, hiring, risk, time)? Any hard limits?
2. **Candidates.** Confirm the list. Ask once: "Is there another option you want included?" If they add none, go ahead with the ones named.
3. **Information.** Do they already have data, notes, benchmarks or links? If yes, use those first and tell them what else you will look up. If no, use `/compare` if available, otherwise search the web or whatever source is available.
4. **Showcase types.** Which kinds of examples do they want to see? Offer options that fit the domain. These are illustrative, so the user can pick several, combine them or add their own. Example Option sets: [basic usage] [with state] [nested components] [compatibility with other libraries] for software libraries; [the same small task in each language] [error handling] [concurrency] for programming languages; [schema and queries] [migration] [backup and restore] for databases; [install and first run] [a typical session] [configuration] for tools; [setup steps] [pricing at their scale] for services; [product photos] [size comparison] [what is in the box] [spec sheet] for physical products. Also offer [audio samples] [video clips] for audio and video gear. Ask which media they want to see (images, audio, video, documents or others), and note that a published page needs small media embedded and large media linked. If examples do not make sense for this domain (for example, comparing laptops), say so and offer a different second tab.
5. **Look and extras.** Color palette (optional), preferred language of the page, any extra tabs they want (for example Migration, Cost, Risks).

## After the answers

- Restate the plan in two lines (goal, candidates, dimensions you will use, showcase types) and start. Do not ask again unless a blocker appears.
- If the user answers only part, proceed with sensible defaults and say which ones you chose.
- Treat the user's priorities as weights only if they state them. Otherwise weights are equal.
