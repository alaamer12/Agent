# Concise Documentation Style

A concise document communicates the complete information needed for its intended purpose using fewer words. It preserves essential meaning, conclusions, requirements, decisions, and necessary context while removing unnecessary repetition and secondary detail.

## Core rule

Concise does not mean incomplete. Do not remove information that is necessary to satisfy the user's request merely to make the document shorter.

## What to retain

- The essential purpose and scope of the work
- Key conclusions and decisions
- Critical requirements or constraints
- Necessary context required for the reader to act or understand
- Evidence that directly supports the main findings (summarized, not expanded)
- Final state or outcomes the user needs

## What to trim

- Redundant restatements of the same point
- Secondary procedural detail not required by the request
- Exhaustive lists of every tool invocation when a summary of the important ones suffices
- Background that does not affect understanding of the result
- Speculative or decorative elaboration

## Structure guidance

Use a tight structure that surfaces the needed information quickly:

- Short introductory statement of purpose or outcome
- Focused sections or bullet lists for findings, decisions, or steps
- Minimal tables or code blocks only when they improve clarity
- Clear final statement of what was resolved and what remains open (if relevant)

Prefer topic or outcome-oriented organization over full chronology unless the user specifically needs the sequence.

## Boundaries

- Never omit required topics, events, errors, or decisions the user asked to include
- Never expand a concise request into a comprehensive report
- When the user asks for "concise," treat that as a hard constraint on length and secondary detail, not as permission to produce an exhaustive document
