# FieldNotes - Agent Rulebook

This file is a rulebook: what agents must do and must read in FieldNotes. It does not describe the
system - the docs it points to do that. Follow it on every task, including work delegated to
subagents.

## 1. Agent Instructions

Stable behavioral rules, independent of version, channel, or phase.

- Do not contradict the docs under `docs/` without verifying the code against them first; when code
  and doc disagree, report the disagreement - never silently pick a side.
- One owner per fact: a rule another section or doc owns is referenced here by pointer, not restated.
- Offline-first is the product premise; a change that assumes connectivity by default is a defect to
  flag, not a detail to slip in.

## 5. Agent Execution and Startup

Before the first change in a session:

1. Read the section-2 mandatory docs.
2. Confirm active context: branch (`canary` unless told otherwise) and version tag.
3. Run the minimum toolchain check that proves MAUI works, or state it was skipped.
4. Units check for implementation tasks (section 2).

During work: report which skill(s) used; stop and ask before any outward VCS action (section 12).

Subagents do NOT start here - they start from the 10.3 block and are bound by the entire rulebook
(see 10.3); this list is for the agent running a session.

## 6. Agents

### 6.1 Premise: a subagent sees no conversation and cannot ask - absent context gets guessed; every rule below follows. Main agent responsibilities:

1. Name each subagent by responsibility (e.g. `sync-conflict-reviewer`), never a generic label.
2. Give complete context up front (goal, files/paths, decisions, output, docs to read) on top of the block.
3. Propagate the duties (4, 6, 7, report) and bound the work: decides alone / returns undecided / must not touch.
4. On fan-out, split scoped subtasks and integrate; collect reports and reconcile contradictions before acting.

### 6.2 Subagent duties

- **The FULL rulebook binds you like the main agent** (block = projection, obey 11/16/18 too).
  Scope narrows ACTIONS, never OBLIGATIONS: no commits/pushes/bumps/VCS changes unless ordered,
  no violations either, no context leaks out of your artifacts.
- Read the docs named in your prompt in full and follow them exactly; do only the scoped task.
- Return out-of-scope items as findings, not changes; reuse over parallel units (4); obey shell/env rules (6-7); write your report (6.4); if the brief is impossible, say so with evidence - do not substitute a goal.

### 6.3 Baseline block - paste at the top of every subagent prompt

> Generated from sections 1-8, 11-13, 16, 18, 21, 23; regenerate on rulebook changes, refill <FILL> slots at paste time. Projection, not second source - volatile facts are slots, policy is text.

```text

The whole rulebook binds you like the main agent; scope limits ACTIONS not obligations - no commits/VCS work unless ordered, no violations, no context leaks (section 7 covers every artifact).
```

### 6.4 Reports

Each subagent writes `.subagents/<name>.md`: goal, actions, files, decisions, verification, open items - the durable working record beyond the returned text. `.subagents/` is gitignored and never committed; reports that leave the repo quote no private path. Fan-out grammar: `x->N1x->N2x`, max 2 depths / 4 workers; a failed leaf is reported, never silently redone.

## 7. Privacy

The project's visibility policy: paths that must not be committed or quoted in artifacts that leave
the repo, and the duties that keep that real.

- Private paths: the skill roots, `scratch/`, `.subagents/` and its reports, and any working-plan
  directory.
- **Cascade:** hiding a producer hides its outputs - reports and snapshots those tools write stay
  private too.
- **Hidden binaries:** the PocketBase client binary stays out of the repo; record where to obtain it
  in the setup notes, not the binary itself.
- **Sync duty:** every private path must also appear in `.gitignore`. If a path is missing there, or
  was tracked before being declared private, **ask the user before clearing the cache**
  (`git rm --cached`); never delete silently.
- `scratch/` and `.subagents/` are gitignored in this repo.

## 8. Resourceful

**Project-local first.** Anything installable/pinnable per-project is: dependencies, toolchains,
interpreters, environments. Global installs are named exceptions, never a convenience default.

- Use the .NET SDK version the repo pins and restore NuGet into the project; do not fall back to a
  machine-global SDK when the repo pins one.
- Run project binaries through the project's own tooling (`dotnet run`, `dotnet test`) so the pinned
  version is the version used.
- Global installs allowed as exceptions: none recorded yet - the .NET SDK install is a per-machine
  prerequisite under section 9's ask, not a silent global default.

## 9. Authority

What agents may do in this environment, and what they must ask about first. Each action is either
**ask per session** (safe default) or **fixed** (granted, with reason).

| Action | Setting |
|---|---|
| Install a binary/package outside the project (system-wide workload, standalone PocketBase server) | ask per session |
| Run external processes (Android emulator, PocketBase daemon, third-party CLIs) | ask per session |
| Write to an existing DB outside scratch/local data (a live/staging PocketBase instance) | ask per session |
| Read or write credentials and secret stores | ask per session |
| Change machine-level config (shell profiles, global config, system services) | ask per session |

- A needed external tool is not forbidden - it is installed under this section's setting, not silently
  and not auto-refused.
- Project-local installs belong to section 8 and do not ask.
- **When a limit blocks the work, say so and ask** (the honest shape) - never improvise around it or
  silently skip the blocked part.

## 12. Git

What the agent may do against this repo, and under whose name.

- **Allowed:** inspecting history and state always (status/log/diff/show); local commits on the working branch per section 3.
- **Ask first:** anything outward-facing - push, pull request, merging into a shared branch, deleting branches, release tags.
- **Never without explicit user order:** history rewrites (rebase/amend/filter of published work), destructive restores (`reset --hard`), workspace purges (`clean`), and never bypass verification hooks (`--no-verify`) to force a check-in - fix the cause instead.
- **Suspend-work (stash):** allowed; every entry named `agent/<task-slug>` so it is identifiable in a shared worktree; restore the exact named entry (never a blind pop) and drop only entries this agent created.
- **Change identity:** commits keep the repository's configured human identity; the human is sole author - no `Co-authored-by` trailer naming the tool or agent. Never edit git config to change authorship. The `commit`/`branch` skills defer to this line.

## 13. Ambiguity

The standing policy for how the agent asks, and how what it decided is recorded.

- **Question mode:** Broad - the user answers intent-level questions; mechanisms, libraries, and
  internals are the agent's to choose, best-for-project. No decisions are currently claimed as Exact;
  the user adds any to this line.
- **[MANDATORY] Ask when the question carries weight:** irreversible, costly, security/compliance,
  cross-module, or product-behavior-changing decisions are ASKED, never silently assumed. Weightless
  questions (placement, naming, routine internals) are decided, never asked.
- **Consequential asks:** route dangerous options (data exposure, irreversible ops, unbounded cost)
  through `caution` so the user sees the card before answering.
- **Before going anonymous** (iwts, delegated runs, hand-offs): ask the critical open questions FIRST;
  what cannot be settled is written as an explicit assumption with its cost, never silently filled.
- **Decision records - this section owns the convention:**
  - **One file per decision** at `docs/decisions/<slug>.md`; a combined `decisions.md` is forbidden (it explodes with project age).
  - **Header anchors:** Date + Commit hash + App-Version (e.g. `1.4.2.dev3`) + Status.
  - **Content order:** question -> context -> real options and why losers lost -> choice -> consequences -> reversal boundary.
  - **The ask-or-decide call is itself a recorded decision** (what was assumed instead of asked), especially before/while anonymous runs.
  - **Run ledger:** `docs/decisions/states.md` (status, remaining, decisions as links, uncertainties, parked findings) - resume reads it, handover writes it.

## 14. Golden Rules

The never-bend list. Each rule names the MECHANISM: the one sanctioned path and the loud failure that
guards it - a bare "don't" is vigilance, and vigilance rots. The Review section hunts these first.

- **Runtime-changeable values have exactly one path:** the typed `SettingsRepository` (SQLite-backed,
  schema-validated at startup, fail-fast on unknown/missing keys). Source literals for such values have
  no reader - the app cannot start on a broken settings schema, so a wrong value is a boot failure, not
  a silent behavior drift.
- **Every query goes through the parameterized builder:** `Query.new(...)` / PocketBase filter
  constructors are the only exported query surface; the raw-string entry point does not exist in the
  codebase, so a SQL-shaped bug is unconstructable rather than discouraged.
- **The service layer is the single DB boundary:** the connection factory is exported only to
  `Services/**` (enforced by the import gate in CI - an out-of-layer import fails the build); pages
  and ViewModels reach data exclusively through services, which is why "UI touched the DB" cannot
  happen quietly.

## 15. Review

**Highest-priority review action, always first:** hunt violations of this rulebook - golden rules above
all, then every other section - in the code AND the docs. A clean scan while bugs exist means the scan
was shallow.

Beneath that pass, this project's named review tasks:

- **Docs:** read all `docs/` content end to end; find stale/outdated passages; find unlinked docs
  nothing points to; any single doc over 500 lines becomes a folder named after the doc, split one
  concern per file with an `index.md` as its local map.
- **DB:** learn every SQLite table; hunt hardcoded/mocked data against section 14 - every literal the
  tables could answer; seeds, not a quota.
- (Growth rule: past ~50 lines keep the always-first rule + a one-line task index here and move full
  task definitions to `docs/review.md`.)

## 16. Facts

The bullets below are **verified facts that contradict what an agent's training or prior knowledge would assume**. The rules are fixed:

- **These facts win over memory.** If a bullet says X and you remember not-X, follow the bullet - your memory is older, and it was wrong here before.
- **A suspect fact gets re-verified, never argued from memory.** Check the current source; if reality moved, update the bullet's date and note what changed (and write a decision record if the update was a decision - section 13).
- **Recording duty, for the whole life of the project:** the moment verification during any task shows a training/prior belief wrong for this project, append a dated bullet in the same change - believed / actual / how it was proven.
- **Bullet format:** `- **<subject>** - <the truth here>. Prior belief: <what memory said>. Verified <YYYY-MM-DD> by <method / source>.`
- Facts describe this project's verified reality as of their date; general knowledge belongs in no file; stale facts are corrected in place with the date moved, not deleted from memory.

- **PocketBase supports SQLite-backed realtime** - realtime subscriptions run over PocketBase's own SQLite store; no separate Postgres is required for FieldNotes' sync. Prior belief: PocketBase realtime requires Postgres. Verified 2026-11-02 by reading the PocketBase docs and running a local subscription test.

## 17. Before-Between-After

Always-on task rituals the user can expect on every piece of work without asking; the guide stays
fixed and the bullets grow as the project learns what must always happen.

- **Override rule:** these apply unless the user's current prompt says otherwise; a standing wish to
  change one is edited HERE (section 11 duty), not remembered informally.
- **Before a task:** none unique - sections 2 and 9 already own what to read and confirm; a ritual
  restating them is noise, so this phase stays empty until the project learns something the other
  sections do not cover.
- **While working:** the section-4 reuse check is re-run at the moment of writing new logic, not only
  at planning - mid-code is where a forgotten unit actually gets duplicated.
- **After finishing:** run `dotnet build` and treat warnings as the gate; self-review the diff against
  the golden rules (section 14).

## 18. Voice

The register the agent speaks and writes in - [concise] (answer first, reasoning on request),
[explanatory] (trade-offs shown), [verbose] (teaching walkthroughs), [ponytail] (the lazy
senior dev: the shortest statement that still proves the point) - illustrative modes; the
choice belongs to the user. The user's own register (their vocabulary, directness, terseness)
sets the level answers are pitched at; questions are framed in their words.

- Agent voice: none recorded yet - until the user chooses, the agent keeps a neutral concise
  default and matches the user's observed register.

- Surfaces may carry different registers - replies to the user / public documents (README,
  release notes) / internal documents (decision records, reports): not yet split; one concise
  voice governs all surfaces until the user names per-surface registers.
- Written reflection: the same voice governs every document and artifact the agent writes -
  `.subagents/` reports, decision records, changelog prose. One voice, spoken and written.

## 19. Sync Blocks

Writable meanings with more than one home. Blocks sync in MEANING, not in letters - each home may
phrase per its platform idiom; drift of what they MEAN is the defect. An edit to one side's
meaning updates every row of that block in the same change (section 11); a moved anchor gets
re-anchored there.

### Block: version-declaration-sites

| Location | Line anchor | Carries |
|---|---|---|
| the MAUI project file | `Version` / `VersionPrefix` properties | the base + the `.devN` build tag, source of truth |
| Android manifest | `versionName` / `versionCode` | the same values in Android's store format (`versionCode` numeric) |
| Windows `Package.appxmanifest` | `Identity Version` | the same base for the Store package |

- The About screen is deliberately NOT a row: it READS the runtime value (section 14) - a reader is
  not a writable home.
