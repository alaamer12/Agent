# Differentiator test — short worked examples

These are deliberately abstract and span different domains, so they illustrate the *test*, not a specific product comparison to imitate.

**Not a real differentiator (both sides achieve it, just differently):**
> Draft claim: "Tool A supports reusable configuration bundles — a key advantage."
> Check: Tool B has macros/templates that produce the same reusable-config outcome, just via a different mechanism.
> Verdict: cut it, or reframe as "both support reusable config, via different mechanisms" only if the mechanism itself matters (e.g. one requires a build step and the other doesn't).

**A real differentiator (only one side can do it):**
> Draft claim: "Tool A can run fully offline with no account; Tool B requires a hosted account to function at all."
> Check: there is no equivalent workaround on Tool B's side — this is a structural capability gap, not a style choice.
> Verdict: keep it, and state why it matters (e.g. "matters for anyone who needs to work without network access, or who can't send data to a third-party server").

**A trap: ecosystem plugin mistaken for core capability:**
> Draft claim: "Tool A has real-time collaboration."
> Check: real-time collaboration is only available through a third-party plugin, not the core product, and adoption of that plugin is low.
> Verdict: mention it, but scoped correctly — "available via a community plugin," not "Tool A has this."
