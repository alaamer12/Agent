# "Why it matters" — short before/after

Without reasoning (a feature name is not an advantage on its own):
> "Tool B has a plugin system — this is a major feature."

With reasoning (the claim earns its place because the consequence is stated):
> "Tool B has a plugin system that lets third parties add new file-format support without waiting on the core maintainers. Why it matters: if you need a format Tool B doesn't support natively, you're not blocked waiting on a roadmap — you (or someone else) can write the plugin."

The pattern to apply, regardless of domain: **feature → concrete consequence for a real task or constraint the reader has.** If the consequence can't be stated concretely, the claim probably isn't a real advantage yet — either dig for the actual impact or cut the line.
