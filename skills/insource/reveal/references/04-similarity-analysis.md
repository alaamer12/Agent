# Similarity analysis - scoring how much of the idea already exists

Similarity is the number the user will read first, so it must be the most defensible thing in the report.
It is *not* name-matching and *not* a feature-count ratio; it is a judgment across ten axes, made explicit,
scored 0-100, and **justified in writing for every competitor**.

## The ten similarity axes

Score each 0-100 (how much the competitor matches the proposed project on that axis), then form the overall:

1. **Core idea** - is it the same concept at all?
2. **Problem** - does it solve the same problem(s), or a different job that looks similar?
3. **Target audience** - the same people, or different people with a similar need?
4. **Features** - the overlap in what it actually does (from the feature matrix, not impressions).
5. **Workflow** - same steps in the same order, or same features serving a different flow?
6. **Business model** - same way of making money (or being free)?
7. **Market** - same geography/segments?
8. **User experience** - same felt product, or same capability delivered differently?
9. **Technical approach** - same implementation strategy, or different tech to the same end?
10. **Value proposition** - does it promise the user the same fundamental benefit?

## The overall score, and its bands

The overall 0-100 is a synthesis of the ten, **not an average** - idea, problem, audience and value
proposition usually carry more weight than technical approach, and the reasoning must say what it weighted.

| Band | Meaning |
|---|---|
| 90-100 | Almost identical concept *and* implementation - this is the idea, already built |
| 75-89 | Very similar product, meaningful overlap - a direct competitor |
| 50-74 | Strongly related, substantial overlap on several axes - a serious competitor to reckon with |
| 25-49 | Partially similar - shares some axes, differs on others; indirect competitor or alternative |
| 0-24 | Weak/remotely related - adjacent, or only a surface resemblance |

## The rules that keep the score honest

- **One high axis does not set the overall.** A competitor that matches the *name* and even the *feature list*
  but targets a different audience and market is not a 90. The overall is earned across the axes that matter,
  and the write-up must show why it is not just the loudest axis.
- **Every score ships with its reasoning.** "78 - same idea, same SMB audience, same freemium model, but
  English-only and no local payment rails, so not 90" - a bare number is unaccountable and the script
  rejects it.
- **Terminology is not difference.** If two products differ only in what they call things, they are similar;
  match on behavior.
- **Similarity ≠ threat.** A 92-similarity product that is dead, and a 55-similarity product that is growing
  fast in the target country, are different problems for the user. Similarity and viability are separate
  columns; the verdict reads both.

## Classify every competitor into the right bucket

The score ranks closeness; the class says *what kind* of competition it is:

- **Direct competitor** - same idea, same audience, same job. The ones that set the bar.
- **Indirect competitor** - same job, different route (different features, model, or audience overlap).
- **Alternative solution** - solves the same underlying problem in a way that isn't a like-for-like product
  (a spreadsheet, an agency, doing nothing, a general tool bent to the job). "Do nothing / DIY" is a real
  alternative and often the truest competitor.
- **Adjacent product** - neighboring capability, could expand into the space, not there yet. Watch-list.
- **Overlapping features, different purpose** - shares many rows of the feature matrix but exists to do
  something else; usually low overall despite high feature overlap - the case that punishes feature-counting.
- **Same audience, different approach** - serves the same people toward the same job by a different mechanism;
  competes for the same wallet and attention without looking like the product.

Classification is what stops the report from being a flat ranked list where a name-collision sits next to a
real rival. Each competitor is placed in exactly one primary class, and the executive summary counts them.
